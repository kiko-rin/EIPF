# Producer Guide: Generating EIPF Files

> This guide describes how to turn a content source into EIPF files. The concrete format of the content source is decided by the producer; this guide only specifies the structural constraints on the EIPF side.

## 1. Prerequisites

- A content source: scripts / assets of each work (text, images, audio, video).
- A working packaging tool or script: parse the content source → generate `body.xhtml` → assemble the three-layer ZIP.
- Resource mapping: resolve resource identifiers in the content source into downloadable URLs.

## 2. Packaging Flow (suggested 5 phases)

| Phase | Description |
|---|---|
| Phase 1 | Parse each scene → generate body.xhtml → extract resource list → build resource path map |
| Phase 2 | Download all resources (retry ≤3 on failure, URL-lowercase fallback) |
| Phase 3 | Build each Entry ZIP → assemble Album ZIPs → collect Series album metadata |
| Phase 4 | Copy `renderer/` and `shared/` (scenario.css / scenario.js) |
| Phase 5 | Write `series.json` and render manifest, then pack the final `.eipfs` |

## 3. Generation Rules Cheat Sheet

### Entry ZIP contents (suggest `ZIP_STORED`)

- `index.json`
- `main.xml`
- `META-INF/manifest.xml`
- `resource/text/body.xhtml`
- `resource/{rtype}/{filename}` (referenced resources)

### Album ZIP contents (`ZIP_STORED`)

- `album.json`
- `entries/<id>.eipf` (one nested ZIP per Entry)

### Series ZIP (outer; Deflate for text / Store for binary)

- `series.json`
- `renderer/`
- `shared/scenario.css`, `shared/scenario.js`
- `resource/render/manifest.json` (optional)
- `albums/<id>.eipfa`

## 4. ID Generation

- Entry / Album IDs: sanitize the source path or title (remove `<>:"/\|?*` and whitespace, replace with `_`), ensuring uniqueness and legal file names.
- Album titles: generated by the producer according to content categories.

## 5. Resource Classification and Download

Classification: `audio` / `backgrounds` / `characters` / `illustrations` / `video`.

Download policy:

- Target path `resource/{rtype}/{filename}`.
- Skip if the file already exists.
- Retry on failure: only 5xx, timeouts and connection errors, at most 3 times.
- URL-lowercase fallback: retry with a lowercased URL after the original fails.

## 6. Verification

Compute a `sha256:`-prefixed checksum for every file and write it into `META-INF/manifest.xml` for integrity verification.

## 7. Optional Security (2.0.1-beta1)

For copyright protection, enable the `security` attribute at packaging time (see `eipf-spec.md` §5):

- **signature**: sign the content hash with the producer's private key, for tamper/forgery resistance.
- **device**: inject `security/license.json` bound to the target device token, to prevent copying/sharing.
- **encryption**: encrypt `resource/` and `renderer/` with AES-256-GCM, to prevent unpacking and reading content.

Implementation suggestions:

- Key pair (RSA-2048): the producer keeps the private key and embeds the public key in the reader.
- Device token: derived from the reader's secure hardware; the user copies it from "Settings" and pastes it into the packager.
- Note: client-side verification is a "cost-raising" measure and cannot absolutely defeat professional reverse engineering.
